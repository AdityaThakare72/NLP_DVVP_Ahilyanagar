Labelling Every Word: Hidden Markov Models and Viterbi

"They can fish." Is "can" a verb or a noun? Is "fish" a verb or a noun? Choose the tags for all the words at once, the best way, without trying every combination.

Day 2 · Session 4 of 5 · sequence labelling

This session builds a part-of-speech tagger from scratch: the black box we used in Day 1, Session 3. It combines Session 3's bigram model (now over tags) with Session 1's word likelihoods (now per tag). The new idea is the Viterbi algorithm, the first real dynamic programming since the edit distance table of Day 1, Session 4. First try: label each word alone

Give every word its most common tag in training. Unknown word: NOUN. On the test sentences: 92.6% correct.

Why not enough

Only 57.1% of unknown words are right, and every ambiguous word gets the same tag in every sentence: "can" is always a verb, even in "a can of soup".

The baseline is real: most frequent tag per word from 3000 training sentences, tested on the remaining 914 sentences (21,662 tokens). 92.6 percent sounds high, but most tokens are easy (the, of, punctuation). The hard tokens are ambiguous or unknown, and that is where the context helps.

Transition P(tag | previous tag)

A bigram model over tags. Real: after DET, a NOUN comes 64% of the time, an ADJ 21%.

Emission P(word | tag)

Of all NOUN tokens, what share is "fish"? Like P(word | class) in Naive Bayes, but the class is the tag.

Hidden weather, visible umbrellas. You never see the weather in another city, only whether your friend carried an umbrella each day. Weather follows weather (transitions); weather causes umbrellas (emissions). From the umbrellas, guess the weather sequence.

"Hidden" means we do not observe the tags at prediction time. "Markov" means each tag depends only on the previous tag, Session 3's assumption. The model is a story of how text could be generated; it is false, but useful, like Naive Bayes.

The real transition table, learned from 3000 sentences

Find: what usually follows DET? What follows ADJ? Which tag usually starts a sentence?

Read a few rows: DET to NOUN 0.64; ADJ to NOUN 0.70; PRON to VERB 0.56; sentence start to NOUN 0.26 or DET 0.24. These probabilities encode grammar: an adjective is followed by a noun, a determiner by an adjective or a noun. Computed with add-0.1 smoothing so no transition is exactly zero.

Why not just try every tag sequence?

sentence lengthtagssequences to score
3 words33 × 3 × 3 = 27
10 words111110 = 26 billion
25 words (a normal WSJ sentence)111125 ≈ 1026

At a billion sequences per second, the 25-word sentence takes longer than the age of the universe. We need a shortcut that still finds the exact best sequence.

From Day 1, Session 4: edit distance had the same problem (too many edit sequences) and the same cure: a table of small subproblems, each built from the previous ones.

11 tags because our universal tag set has 11 tags in this data (the X tag for traces is removed). 11 to the 25 is about 1.1 times 10 to the 26. The age of the universe is about 4 times 10 to the 17 seconds, so even a billion per second needs 10 to the 17 seconds, comparable to it. The point: exponential growth.

The Viterbi idea: keep only the best way to reach each tag

Driving from Pune to Delhi through one city per stage. To find the best route into Bhopal, you need only the best routes into each city of the previous stage, plus the last road. You never need to remember the worse routes into those cities.

The table

One row per tag, one column per word. Cell (tag t, word i) = probability of the best tag sequence for words 1..i that ends in t.

The rule for one cell

For each previous tag p: (cell of p) × P(t | p). Take the maximum. Multiply by P(word i | t). Remember which p won (a backpointer).

At the end, take the best cell in the last column and follow the backpointers to read off the whole sequence. Work: words × tags × tags. For 25 words and 11 tags: about 3,000 steps instead of 1026.

Named after Andrew Viterbi (1967), originally for decoding noisy radio signals; it runs in every mobile phone. The key property: the best path to a cell must pass through the best path to some previous cell. That is what lets us throw the rest away. 25 x 11 x 11 = 3,025.

Column 3: NOUN = max(0.0288 x 0.5, 0.0009 x 0.3) x 0.2 = 0.00288, from VERB; VERB = max(0.0288 x 0.3, 0.0009 x 0.5) x 0.1 = 0.000864. Best last cell: NOUN. Trace back: NOUN from VERB from PRON. The brute force table confirms it is the top of all 27.

Viterbi in Python: two loops and a max

def viterbi(words, tags, start, trans, emit):
    V = [{}]; back = [{}]
    for t in tags:                                   # first column: start transition x emission
        V[0][t] = start[t] * emit[t].get(words[0], 0)
    for i in range(1, len(words)):                  # outer loop: one column (word) at a time
        V.append({}); back.append({})
        for t in tags:                               # inner loop: one cell (tag) in this column
            best = max(tags, key=lambda p: V[i-1][p] * trans[p][t])   # best previous tag
            V[i][t] = V[i-1][best] * trans[best][t] * emit[t].get(words[i], 0)
            back[i][t] = best                         # remember where we came from
    last = max(tags, key=lambda t: V[-1][t])          # best cell in the last column
    path = [last]
    for i in range(len(words) - 1, 0, -1):            # walk the backpointers right to left
        path.append(back[i][path[-1]])
    return path[::-1]                                 # reverse: left to right

Loops

Outer: columns (words). Inner: cells (tags). Inside max: a hidden third loop over previous tags.

Real version

Use log probabilities and add instead of multiply, or 25 words of tiny numbers underflow to 0 (Session 1).

The same structure as edit distance: a table, cells filled left to right, each from the previous column, and a trace back at the end. The notebook version uses logs and also the end transition to the end marker.

The new difficulty: 10.2% of test tokens are words never seen in training. Their emission probability is 0 for every tag.

Training takes well under a second. Tagging the 914 test sentences took about 1.5 seconds in plain Python. The next slide deals with unknown words.

Unknown words: use the shape of the word

An unseen word still tells us something: Capitalised? Contains a digit? Ends in -ing, -ed, -ly, -s?

Trick: words seen once behave like unknown words (Session 3's <unk> idea). Group them by shape. For a new word, P(word | tag) = share of the tag's tokens that were once-only words of the same shape.

Unknown-word accuracy: 59.7% with one <unk> for all, 81.8% with 8 shape groups.

The 8 shapes are: digit, Capital, -ing, -ed, -ly, -s, hyphen, other, checked in that order. Capitalised words are mostly proper nouns, which the universal tag set calls NOUN. This is hand-made feature engineering; the next generation of taggers (CRFs, then neural networks) learn such features themselves.

Where the HMM breaks

One tag of memory

Each tag depends only on the previous tag. Agreement or structure further back is invisible, as with bigrams in Session 3.

Words cannot share information

Emission P(word | tag) treats "run", "runs", "running" as unrelated. Shape features were bolted on by hand.

Generates, does not discriminate

It models how words are produced from tags, then inverts with Bayes, like Naive Bayes. Models that score tags directly from rich features (CRFs, neural taggers) do better.

Why still learn it

The ideas (hidden states, transitions, Viterbi decoding) are in speech recognition, gene finding, and the decoding step of modern NER and translation systems.

The progression in industry: HMM (1990s), CRF with hand features (2000s), BiLSTM-CRF (2015), transformer fine-tuning (2018 on, Day 3). Viterbi decoding survives inside the CRF layer of many of them.

  5. Run Viterbi with logs on the real model; tag all test sentences; accuracy on known and unknown words

Step 7 brings back the movie reviews: the reviews are lowercased, which breaks the Capitalised shape and makes many names look like ordinary words. A real example of training and use data not matching.

Common mistakes in this session

Emission the wrong way round. It is P(word | tag), not P(tag | word).

Choosing the best tag per column. That is not Viterbi; follow the backpointers from the end.

Multiplying probabilities over long sentences. Use logs.

Forgetting unknown words. An emission of 0 for every tag kills every path.

Off-by-one in the backtrack. Column i stores the best previous tag for column i - 1.

Comparing with a tagger trained on the test data. Know where the reference was trained.

The second mistake is subtle: taking the highest cell in each column separately can produce a sequence whose transitions are impossible. Only the backpointers guarantee a consistent best sequence.

Recap, and the problem we are left with

  • Sequence labelling gives every token a label; context decides ambiguous and unknown words.
  • An HMM: a bigram model over hidden tags (transitions) + word likelihoods per tag (emissions), both by counting.
  • Viterbi finds the exact best tag sequence with a table and backpointers: words × tags × tags work instead of tagswords.
  • On real text: 95.2%, mostly thanks to handling unknown words by their shape.
Still unsolved, and Session 5 starts here: a tag labels one word. But "Steven Spielberg", "New York", "the Academy Awards" are single things spread over several words. How do we label spans, decide what kind of thing each is, and then find who did what to whom in a sentence?

Session 5 turns spans into per-word labels with the BIO scheme, so named entity recognition becomes sequence labelling, the same problem as today. Then dependency parsing gives the sentence structure.
